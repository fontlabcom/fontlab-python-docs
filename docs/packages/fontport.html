    Fontport

    Fontport connects FontLab 9 to FontParts, UFO and DesignSpace data, and to the fontTools, fontPens and ufoLib2 libraries around them. It provides point pens over native FontGate glyphs, detached FontParts and UFO snapshots, and live FontParts objects bound to an open FontLab document.

    No user interface

    Fontport has no UI. Its Qt editors now live in fontlabapp.fontui.

    Install

    Fontport requires fontlab-fontlabapp (version 0.2.26.dev150 or later), plus defcon, fontTools, fontPens, FontParts and ufoLib2. Fontlabapp is not on a package index, so install it from a checkout or wheel first, then Fontport, into FontLab's Python folder; see Install into FontLab. Importing the package outside FontLab is safe; native access loads on demand.

    Quick start

    Draw into a native glyph with a fontTools pen:

    # Inside FontLab, with a glyph you own
from fontlab_fontport.pens import FontGatePointPen
from fontTools.pens.pointPen import SegmentToPointPen

pen = SegmentToPointPen(FontGatePointPen(glyph))
pen.moveTo((0, 0))
pen.lineTo((200, 0))
pen.lineTo((100, 300))
pen.closePath()

    Examples

    Edit a detached FontParts copy, then write it back explicitly:

    from fontlab_fontport.transfer import to_fontparts, write_glyph

snapshot = to_fontparts(native_glyph)     # a real fontshell RGlyph
snapshot.width = 600
write_glyph(snapshot, target_glyph)       # explicit destination

    Bind live FontParts objects to an open FontLab document:

    from fontlab_fontport.host import NativeFontBackend
from fontlab_fontport.live import RFont

font = RFont(NativeFontBackend(font_id))  # font_id: the document's FontLab id
font["A"].width = 600                     # updates the FontLab glyph
font.close()                              # detaches; the document stays open

    Stage font information and apply it in one validated batch:

    font.info.apply({"familyName": "My Family", "ascender": 810.5},
                undo_name="Edit font information")

    UFO and DesignSpace

    Fontport exports a whole FontLab font to UFO and DesignSpace, and opens UFO and DesignSpace files as new FontLab documents.

    Export a multi-master font as a .designspace plus one UFO per master. This example needs FontLab, because it reads a live font:

    from fontlab_fontport.designspace_io import export_designspace

path, losses = export_designspace(backend, "/absolute/path/Family.designspace")
print(path)
print(*losses, sep="\n")          # what the export did not carry

    export_designspace(backend, destination, document=None) reads the backend and never changes it. Axes, master locations and instances come from the native package unless you pass your own DesignSpaceDocument. Each master is written as <stem>-<master>.ufo beside the .designspace, with its own outlines, anchors and kerning. write_designspace(font, document, destination, master_kerning) does the file writing for a font you already exported. Nothing is overwritten.

    Open UFO and DesignSpace files through FontLab's native open_font (this also needs FontLab):

    from fontlab_fontport.native_import import import_designspace, import_ufo_native

backend = import_designspace("/absolute/path/Family.designspace")
# or: import_ufo_native("/absolute/path/Master.ufo")  # one master
backend.close()                    # the result is an owned document

    Both need absolute paths, a matching suffix and an existing file; FontLab resolves the source UFOs of a designspace. Import converts nothing in Fontport.

    The file writing itself runs without FontLab. This example splits a ufoLib2 font whose layers are the masters into Family.designspace and one UFO per master, with each master's own kerning:

    from fontTools.designspaceLib import (
    AxisDescriptor, DesignSpaceDocument, SourceDescriptor)
from ufoLib2 import Font
from fontlab_fontport.designspace_io import write_designspace

font = Font()
font.layers.renameLayer(font.layers.defaultLayer.name, "Light")
font.layers.newLayer("Bold")
for layer in font.layers:
    layer.newGlyph("A").width = 500

doc = DesignSpaceDocument()
axis = AxisDescriptor(name="Weight", tag="wght", minimum=300, default=300, maximum=700)
doc.addAxis(axis)
for name, weight in (("Light", 300), ("Bold", 700)):
    doc.addSource(SourceDescriptor(name=name, location={"Weight": weight}))

kerning = {"Light": {("A", "A"): -50}, "Bold": {("A", "A"): -80}}
path = write_designspace(font, doc, "/absolute/path/Family.designspace", kerning)

    Every source name must be a layer of the font, and nothing is overwritten.

    What an export loses. The losses list names it: designspace rules, axis and location labels, instances' generated UFOs (instances are listed only), and per-master groups, info, lib and features, which come from the key master and are shared by every master UFO. Brace layers are not exported. Kerning is the exception: each master's own kerning is exported.

    Why Fontport does not use fgFont.save("x.ufo"). The native UFO save is lossy. In a measured case it wrote the current master only (a three-master font gave one layer), no kerning.plist, and no anchors. The MCP save_font tool writes only VFJ, VFC and VFJP. Fontport's own exporter reads every master, so it keeps all masters, kerning and anchors. Use VFJ when you need a lossless native archive. See docs/UFO-INTERCHANGE.md in the Fontport repository for the full table.

    The editors moved to Fontlabapp

    The six FontParts-bound Qt editors (font_info_editor, groups_editor, kerning_editor, transform_editor, batch_panel and glyph_sequence) live in fontlabapp.fontui. They call Fontport lazily, so install both packages in the same environment (Fontlabapp first). Once both are published, the Fontlabapp fontport extra installs Fontport for you.

    # old (removed): from fontlab_fontport.ui import font_info_editor
from fontlabapp.fontui import font_info_editor

    fontlab_fontport.ui remains for one release as a tombstone: reading any name from it raises ImportError("fontlab_fontport.ui moved to fontlabapp.fontui"). The batch panel still starts a separate Python 3.11+ process that needs fontlab-fontport. Vanilla support moved to fontlab_glyport.ui.session.

    Fontport also reads and writes feature blocks (fontlab_fontport.feature_blocks: read_feature_blocks and write_feature_blocks), which need the original font to be active and compare the source snapshot before writing.

    Behaviour and limits

    • Undo: an edit through the live binding is undone by the first Edit > Undo. FontLab records one extra, empty Undo row with it (exact one-row Undo is the unsupported capability glyph.exactSingleUndo; information batches likewise report info.exactSingleUndo).
    • Font information: metrics (ascender, descender, capHeight, xHeight, italicAngle), styleName and note are written to the current key master only; family name, version fields, copyright and units per em are stored on the font. Supported fields: familyName, styleName, unitsPerEm, ascender, descender, capHeight, xHeight, italicAngle, versionMajor, versionMinor, note and copyright. The structured fields openTypeOS2Panose, openTypeOS2WeightClass, openTypeOS2WidthClass, postscriptStemSnapH and postscriptStemSnapV are also written to the key master only. OpenType name records are refused, since FontLab does not persist them through this route.
    • Default and strict modes: the v1.0.0 editing contract is the default. Stricter guarantees are opt-in: require_single_undo=True on font.info.apply and require_persistence=True on group and save operations refuse instead of accepting the extra Undo row or a legacy group mode.
    • Named refusals: layer create, delete and rename; glyph rename; guidelines and images; hinted outlines; fractional anchors and kerning; non-ASCII names for new glyphs and groups; multi-layer UFO import; world selection. Each raises UnsupportedCapability with its name before anything is written.
    • font.capabilities() lists every capability with its evidence. Edits made in FontLab itself do not notify the binding: call font.refresh() and reacquire glyph and layer handles afterwards.
    • FontParts coverage (FontParts 1.1.1 upstream tests, host-free backend run): 1,748 of 1,797 pass, 48 raise a named UnsupportedCapability, one is skipped upstream, none fail unclassified. These are not FontLab-native passes.
    • An unexpected FontLab error during the final write can leave partial changes; develop on a copy of your font.
