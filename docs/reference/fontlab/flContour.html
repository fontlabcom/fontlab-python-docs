    fontlab.flContour

    flContour

    A contour is the closed or open path that forms a letter's shape. Everything you see when you look at a glyph in the editor — the outer edge of an "H", the bowl of a "p", the counter inside an "O" — is a contour. Each contour is made up of an ordered sequence of flNode objects connected by curve and line segments. The contour is the level at which you think about the overall shape of a letter part, while nodes are the individual control points that define exactly where the path goes.

    Inherits from flObject.

    What Is a Contour?

    Open vs. closed contours. Most glyphs consist entirely of closed contours — the path's last node connects back to its first node, enclosing an area. Closed contours are what you use for all regular letterforms. An open contour, by contrast, has two free endpoints that don't connect. Open contours appear in some decorative or component-based designs, in stroke-based workflows where a skeleton is later expanded, and in glyphs built from paths that are meant to be processed further rather than filled directly. The closed property tells you which kind you have.

    Winding direction and why it matters. In digital type, a filled shape is defined not just by its path but by the direction the path travels — clockwise or counter-clockwise. FontLab follows the PostScript convention: outer contours wind counter-clockwise and counter-shapes (holes) wind clockwise. The letter "O", for example, is built from two contours: the outer oval winds counter-clockwise, and the inner counter-oval winds clockwise — together they create a filled ring. If you get the directions wrong, the font renderer may fill the hole or leave the outer shape empty. The clockwise property and the setStartPoint method (combined with a direction reversal) are your tools for managing this. When scripting, always verify and normalize winding direction after building contours programmatically.

    Tutorial: Building the Letter "O" from Two Contours

    The letter "O" is the classic test case for understanding contour structure in font design. It requires exactly two contours: the outer oval (counter-clockwise, the positive shape) and the inner counter-oval (clockwise, the hole). This tutorial builds a simplified circular "O" from scratch using flContour and flNode, demonstrating the key concepts of contour construction, node types, smooth nodes, and winding direction.

    import fontlab as fl
from fontlab import flContour, flNode

font  = fl.CurrentFont()
glyph = font['O']
layer = glyph.layers[0]
shape = layer.shapes[0]

    # ── Step 1: Understand the existing "O" ─────────────────────────────────────
# A real "O" glyph will already have two contours. Let's inspect them to
# understand what winding direction and node count to expect.
for i, contour in enumerate(shape.contours):
    direction = "clockwise (inner)" if contour.clockwise else "counter-clockwise (outer)"
    print(f"Contour {i}: {contour.nodesCount} nodes, {direction}, closed={contour.closed}")

    # ── Step 2: Build the outer oval (counter-clockwise) ────────────────────────
# A circle in Bézier representation needs 4 on-curve nodes (at 12, 3, 6, 9 o'clock)
# and 8 off-curve handles. The magic constant 0.5523 gives excellent circle approximation.
# We place nodes counter-clockwise: top → left → bottom → right.

k = 0.5523   # Bézier circle approximation constant
cx, cy = 250, 350   # center of the O
rx, ry = 200, 250   # horizontal and vertical radii

outer = flContour()
outer.closed = True

# Top on-curve node (12 o'clock), going counter-clockwise
outer.add(flNode(cx,        cy + ry,              nodeType='on'))   # top
outer.add(flNode(cx - rx*k, cy + ry,              nodeType='off'))  # outgoing handle
outer.add(flNode(cx - rx,   cy + ry*k,            nodeType='off'))  # incoming handle
outer.add(flNode(cx - rx,   cy,                   nodeType='on'))   # left
outer.add(flNode(cx - rx,   cy - ry*k,            nodeType='off'))  # outgoing handle
outer.add(flNode(cx - rx*k, cy - ry,              nodeType='off'))  # incoming handle
outer.add(flNode(cx,        cy - ry,              nodeType='on'))   # bottom
outer.add(flNode(cx + rx*k, cy - ry,              nodeType='off'))  # outgoing handle
outer.add(flNode(cx + rx,   cy - ry*k,            nodeType='off'))  # incoming handle
outer.add(flNode(cx + rx,   cy,                   nodeType='on'))   # right
outer.add(flNode(cx + rx,   cy + ry*k,            nodeType='off'))  # outgoing handle
outer.add(flNode(cx + rx*k, cy + ry,              nodeType='off'))  # incoming handle
# (path closes back to the top node)

print(f"Outer contour: {outer.nodesCount} nodes, clockwise={outer.clockwise}")

    # ── Step 3: Make the on-curve nodes smooth ───────────────────────────────────
# Setting smooth=True on the on-curve nodes ensures the handles are treated as
# collinear — producing the fluid, tangent-continuous curve transitions that
# make a circle look like a circle, not a polygon.
for node in outer.nodes():
    if node.isOn():
        node.smooth = True

    # ── Step 4: Build the inner counter (clockwise) ─────────────────────────────
# The inner oval is smaller and must wind in the OPPOSITE direction to create
# a hole. We build it clockwise: top → right → bottom → left.
# Using smaller radii for the counter.
irx, iry = 130, 170   # inner radii

inner = flContour()
inner.closed = True

# Top on-curve node, going CLOCKWISE: top → right → bottom → left
inner.add(flNode(cx,        cy + iry,              nodeType='on'))
inner.add(flNode(cx + irx*k, cy + iry,             nodeType='off'))
inner.add(flNode(cx + irx,   cy + iry*k,           nodeType='off'))
inner.add(flNode(cx + irx,   cy,                   nodeType='on'))
inner.add(flNode(cx + irx,   cy - iry*k,           nodeType='off'))
inner.add(flNode(cx + irx*k, cy - iry,             nodeType='off'))
inner.add(flNode(cx,        cy - iry,              nodeType='on'))
inner.add(flNode(cx - irx*k, cy - iry,             nodeType='off'))
inner.add(flNode(cx - irx,   cy - iry*k,           nodeType='off'))
inner.add(flNode(cx - irx,   cy,                   nodeType='on'))
inner.add(flNode(cx - irx,   cy + iry*k,           nodeType='off'))
inner.add(flNode(cx - irx*k, cy + iry,             nodeType='off'))

# Make on-curve nodes smooth
for node in inner.nodes():
    if node.isOn():
        node.smooth = True

print(f"Inner contour: {inner.nodesCount} nodes, clockwise={inner.clockwise}")

    # ── Step 5: Verify winding directions ────────────────────────────────────────
# Before adding the contours, make sure winding is as expected.
# Outer should be counter-clockwise (False), inner should be clockwise (True).
# getSquare() returns positive for CCW, negative for CW.
print(f"Outer area (positive = CCW): {outer.getSquare():.1f}")
print(f"Inner area (negative = CW):  {inner.getSquare():.1f}")

    # ── Step 6: Add both contours to the shape and update ───────────────────────
# clearNodes on existing contours first if this is a re-run of the script:
for existing in list(shape.contours):
    shape.removeContour(existing)

shape.addContour(outer)
shape.addContour(inner)

fl.Update()
print("Done! The letter O has been rebuilt.")

    Common Scripting Patterns

    These self-contained examples solve the tasks that come up most often when working with contours in scripts.

    Reverse winding direction of all counter-shapes

    When importing outlines, the winding direction can come in wrong. This script identifies any clockwise outer contour (which should be counter-clockwise) and any counter-clockwise inner contour (which should be clockwise) and fixes them. The heuristic used here is area: the largest contour by area is assumed to be the outer shape.

    import fontlab as fl

font  = fl.CurrentFont()
glyph = font['O']
layer = glyph.layers[0]

for shape in layer.shapes:
    contours = shape.contours
    if not contours:
        continue

    # Find the contour with the largest absolute area — that's the outer shape.
    areas = [(abs(c.getSquare()), c) for c in contours]
    areas.sort(reverse=True)
    outer_contour = areas[0][1]

    for area, contour in areas:
        is_outer = (contour is outer_contour)
        # Outer should be CCW (clockwise=False); inners should be CW (clockwise=True)
        if is_outer and contour.clockwise:
            contour.reverse()
            print(f"Reversed outer contour in '{glyph.name}'")
        elif not is_outer and not contour.clockwise:
            contour.reverse()
            print(f"Reversed inner contour in '{glyph.name}'")

    Find all open contours in the font

    Open contours are usually unintentional in a production font. This script lists every open contour by glyph name so you can investigate and close them.

    import fontlab as fl

font = fl.CurrentFont()
open_found = []

for glyph in font.glyphs:
    for layer in glyph.layers:
        for shape in layer.shapes:
            for contour in shape.contours:
                if not contour.closed:
                    first = contour.getFirstPoint()
                    last  = contour.getLastPoint()
                    open_found.append(
                        f"{glyph.name} [{layer.name}]: "
                        f"open contour with {contour.nodesCount} nodes, "
                        f"start=({first.x():.0f},{first.y():.0f}), "
                        f"end=({last.x():.0f},{last.y():.0f})"
                    )

if open_found:
    print(f"Found {len(open_found)} open contour(s):")
    for line in open_found:
        print(" ", line)
else:
    print("No open contours found.")

    Add extremum nodes to all contours

    Extremum nodes — points at the topmost, bottommost, leftmost, and rightmost positions of a curve — are required for correct PostScript hinting. This script inserts them where they are missing by using insertNodeTo at the parametric position of each extremum.

    import fontlab as fl

font  = fl.CurrentFont()
glyph = font['O']
layer = glyph.layers[0]

for shape in layer.shapes:
    for contour in shape.contours:
        nodes = contour.nodes()
        for node in nodes:
            if node.isOn():

    Simplify all contours by removing redundant nodes

    After auto-tracing or importing from SVG, outlines often contain far too many nodes. This script applies the simplify method to each contour to reduce node count while preserving the visual shape within a tolerance of 1 em unit.

    import fontlab as fl

font  = fl.CurrentFont()
tolerance = 1.0    # maximum deviation from original shape, in em units

for glyph in font.glyphs:
    for layer in glyph.layers:
        for shape in layer.shapes:
            original_count = sum(c.nodesCount for c in shape.contours)
            for contour in shape.contours:
                contour.simplify(
                    tolerance,
                    lossy=False,    # keep within tolerance
                    extremes=True   # always preserve extreme nodes
                )
            new_count = sum(c.nodesCount for c in shape.contours)
            if new_count < original_count:
                print(f"{glyph.name}: {original_count} → {new_count} nodes")

    Check contour compatibility across masters for variable fonts

    Variable font masters must have the same number and type of nodes on each corresponding contour. This script compares the first two masters of a variable font and reports any incompatible glyphs.

    import fontlab as fl

font   = fl.CurrentFont()
glyphs = font.glyphs

for glyph in glyphs:
    if len(glyph.layers) < 2:
        continue
    layer_a = glyph.layers[0]
    layer_b = glyph.layers[1]

    contours_a = [c for s in layer_a.shapes for c in s.contours]
    contours_b = [c for s in layer_b.shapes for c in s.contours]

    if len(contours_a) != len(contours_b):
        print(f"INCOMPATIBLE {glyph.name}: "
              f"{len(contours_a)} vs {len(contours_b)} contours")
        continue

    for i, (ca, cb) in enumerate(zip(contours_a, contours_b)):
        if not ca.isCompatible(cb, strong=True):
            print(f"INCOMPATIBLE {glyph.name} contour {i}: "
                  f"{ca.nodesCount} vs {cb.nodesCount} nodes")
