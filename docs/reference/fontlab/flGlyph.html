    fontlab.flGlyph

    flGlyph

    A glyph is your font's record for one character — the letter "A", the numeral "3", an ampersand, or any other symbol you draw. Think of it as a folder: the glyph holds your drawings (called layers), the character code it maps to (unicodes), the spacing information (metrics), and any organisational labels (tags) you want to attach.

    Inherits from flObject.

    What is a Glyph?

    The shape of a glyph

    The glyph itself doesn't contain drawing data directly. Instead it holds one or more layers. Each layer is a snapshot of the character at a particular design stage or design-space location:

    • Master layers (one per master in a variable font) are the interpolatable drawings that define your design space. In a simple single-master font there is just one — often called "Regular".
    • Service layers are helpers: the mask, reference drawings, or intermediate states used during editing. They do not export.

    So when you draw the letter "A", you are drawing on a layer inside the glyph, not on the glyph itself. This distinction matters when scripting: to read or change actual node coordinates you go glyph → layer → shape → contour → node.

    Unicodes

    A unicode is the number that maps your glyph to a character in the Unicode standard. "A" is 0x0041, "α" is 0x03B1. A glyph can have more than one unicode (for example the standard "A" and its fullwidth variant "Ａ" can share a single drawing). The font system uses unicodes to figure out which glyph to show when text is set.

    Metrics

    The advance width is how much horizontal space the glyph occupies — including any side-bearings. The left sidebearing is the gap between the glyph's left edge and the start of its outline; the right sidebearing is the gap on the other side. You can set these as raw numbers or as expressions that reference other glyphs (e.g. "=n" means "copy the left sidebearing from the glyph n"). Expressions let you keep spacing consistent across a family without maintaining numbers by hand.

    Tags

    Tags are free-form labels you attach to a glyph. They are invaluable for organising large font projects: tag all diacritics as "diacritic", all small caps as "sc", all glyphs that still need review as "todo". You can then filter or select glyphs by tag in the font window.

    Common Patterns

    Iterating every glyph and checking content

    font = fl.CurrentFont()
for glyph in font.glyphs:
    if not glyph.hasBody:
        print(f"Empty glyph: {glyph.name}")

    Finding a glyph and reading its active layer

    glyph = font['A']
layer = glyph.layers[0]         # first (usually Regular) master layer
print(layer.name, layer.advanceWidth)

    Adding and removing tags

    # Tag all glyphs that still need spacing work
for glyph in font.glyphs:
    if glyph.advanceWidth == 0:
        glyph.setTag("no-width", True)

# Later, remove the tag after fixing
glyph.setTag("no-width", False)

    Batch-setting sidebearings with a metric expression

    # Make every lowercase letter inherit its left bearing from 'n'
import fontlab as fl
font = fl.CurrentFont()
lowercase = "abcdefghijklmnopqrstuvwxyz"
for name in lowercase:
    g = font.findName(name)
    if g:
        g.metricsLeft = "=n"

    Copying a glyph

    from fontlab import flGlyph
original = font['A']
copy = flGlyph(original)   # independent clone
copy.name = "A.ss01"
font.addGlyph(copy)

    Tutorial

    import fontlab as fl
from fontlab import flGlyph, flLayer, flShape, flContour, flNode

# ============================================================
# Get the current font and look at a glyph
# ============================================================

font = fl.CurrentFont()

# Access the glyph for the letter 'A'. The font acts like a
# dictionary — you can look glyphs up by name.
glyph = font['A']

# The advance width is the total horizontal space this character
# takes up in a line of text (left sidebearing + outline + right
# sidebearing).
print(f"Glyph: '{glyph.name}'")
print(f"Advance width: {glyph.advanceWidth} units")

# ============================================================
# Layers — one per master, plus service layers
# ============================================================

# Each glyph can have several layers. In a variable font you'll
# see one per master (e.g. "Light", "Regular", "Bold"). In a
# single-master font there is usually just one.
for layer in glyph.layers:
    print(f"  Layer '{layer.name}'  — width: {layer.advanceWidth}")

# The active layer is the one shown in the glyph editor right now.
active = glyph.activeLayer
print(f"Active layer: '{active.name}'")

# ============================================================
# Tags — organise your glyph set
# ============================================================

# Add a tag to mark this glyph for review:
glyph.setTag("needs-review", True)

# Read back the tags:
print("Tags:", glyph.tags)              # explicit tags you set
print("Auto-tags:", glyph.virtualTags())  # tags FontLab derives automatically

# Remove a tag once work is done:
glyph.setTag("needs-review", False)

# ============================================================
# Metrics — read and write sidebearings
# ============================================================

# Read both sidebearings at once (no italic transform needed here):
from PythonQt.QtGui import QTransform
identity = QTransform()
lsb, rsb = glyph.getSB(identity)
print(f"Left SB: {lsb}   Right SB: {rsb}")

# Set the left sidebearing directly:
glyph.setLSB(40.0, False, identity)

# Or use metric expressions so this glyph inherits spacing from 'H':
glyph.metricsLeft  = "=H"
glyph.metricsRight = "=H"
# Now tell FontLab to re-evaluate the expressions:
glyph.updateSidebearings(True)

# ============================================================
# OpenType glyph classification
# ============================================================

# Mark a glyph as a ligature (two components):
ligature = font.findName("f_i")
if ligature:
    ligature.otGlyphClass   = 2    # 2 = ligature
    ligature.otLigaturesCount = 2  # composed of 2 glyphs (f + i)

# Mark a glyph as a combining mark:
acute = font.findName("acutecomb")
if acute:
    acute.otGlyphClass = 3    # 3 = mark

# ============================================================
# Creating a brand new glyph from scratch
# ============================================================

# Create a detached glyph object:
new_glyph = flGlyph()
new_glyph.name    = "diamond"
new_glyph.mark    = 3   # colour-mark it so it's easy to spot

# Build a layer to hold the outline:
layer = flLayer()
layer.name  = "Regular"
layer.advanceWidth = 400   # advance width for this master

# Build the outline: a diamond shape made of 4 on-curve nodes.
# The path goes: bottom → right → top → left, closed.
shape   = flShape()
contour = flContour()
contour.closed = True
for x, y in [(200, 0), (400, 300), (200, 600), (0, 300)]:
    contour.add(flNode(x, y, nodeType='on'))

shape.addContour(contour)
layer.addShape(shape)

# Attach the layer to the glyph, then add the glyph to the font:
new_glyph.addLayer(layer)
font.addGlyph(new_glyph)

# Tell FontLab to refresh the UI:
fl.Update()

    Glyph-only mark encoding and history

    glyph.glyphMark exposes the existing FontLab integer, not a Glyphs label index. Nonpositive values render as no mark. Values 1–360 encode hue (value - 1). Values above 360 render as gray, with channel value min(255, lightness // 2 + max(0, value - 1000) // 2) using the current mark lightness setting. Thus 1000 uses the base gray and 1100 is 50 channel units lighter; neither specifies a fixed RGB gray across preferences. VFJ stores the integer. There is no categorical conversion from Glyphs label 11 to a FontLab charcoal label. Converting an achromatic QColor through the hue-based color adapter yields no mark and is not a substitute for this integer property.

    The raw property is suitable when the caller manages change notification and history. Ordinary glyph history can import geometry to serialize a full snapshot. This binding does not provide a geometry-free metadata transaction, cross-document atomicity, or automatic rollback. Do not emulate glyph-only writes by changing mark and restoring layers: that can make inherited layer marks explicit. Existing scripts that use mark retain its previous behavior.

    Sigma authoring data

    The binding exposes the native Sigma metadata used for authored interpolation adjustments:

    Method Result and behavior
    getSigmaData() Return an editable dictionary snapshot of the glyph's Sigma metadata.
    setSigmaData(data) Validate and apply a complete dictionary through the native Sigma authoring path; invalid data raises ValueError. The native operation records the edit in history.
    clearSigmaData() Remove authored Sigma curves through the native editing path; errors raise ValueError.
    initializeSigma() Bind compatible master points for Sigma, record the initialization in history, and return None. Errors raise ValueError.

    Read the dictionary with getSigmaData() before editing it; retain unrelated keys and use the native validator rather than inventing a metadata schema. setSigmaData() and clearSigmaData() also return None on success. The current registration docstring for initializeSigma() says dict, but the implementation returns None; call getSigmaData() afterward to inspect the initialized data.
