    fontlabapp.objects.json_data

    json_data

    FontLab 9.1 object JSON: read, edit, copy, save and paste glyphs, layers, elements and contours.

    What: FontLab 9.1 (build 9812 and later) can write glyphs, layers, elements and contours as JSON and read that JSON back into new, detached objects: fontlab.flModelProducer.getClipboardDataJson(package_id, upm, objects) returns a QByteArray and getObjectsFromJsonData(data) returns a list, or None when it cannot read the data. This module gives that pair a safe Python surface.

    The pure layer needs no FontLab. Envelope.parse reads the JSON envelope ("dataType": "com.fontlab.objects", "upm", "packageId" and one payload: a singleton "glyph", "layer", "element" or "contour" key for one object, "objects": [{"glyph": {...}}, ...] for two or more, and no payload key for an empty list). Envelope.to_bytes writes the same shapes back. describe lists what the data holds, and rename_glyphs, unique_glyph_names, filter_layers, set_advance_width and drop_unicodes return edited copies.

    The native layer runs inside FontLab: available, export, decode, copy_to_clipboard, read_clipboard, save_file, load_file, paste_glyphs and paste_shapes.

    How: decode always hands FontLab a PythonQt.QtCore.QByteArray. Passing Python bytes, bytearray or str to getObjectsFromJsonData crashes FontLab 9.1.9812 (SIGBUS), so no other type reaches it. None from FontLab becomes ValueError. Decoded objects are detached: a decoded glyph has a new id and no font, and flGlyph has no unicode attribute, so Unicode values come from the JSON. upm is ignored on decode; nothing is scaled.

    paste_glyphs never calls flPackage.addGlyph (a raw insert without Undo that also produced duplicate names live). It creates glyphs through fontlabapp.glyphs.creation.create_glyphs and copies the decoded outlines in its fill step. paste_shapes adds decoded shapes to one live layer inside one fontlabapp.core.history.glyphs.commit.

    Undo: the JSON calls record nothing. paste_glyphs: each new glyph is its own Undo step (FontLab's Add Glyph) and the outlines are one more named step. paste_shapes: one named Undo step. Everything else changes no font.

    Clipboard: FontLab 9.1 puts this JSON on the clipboard as application/json (seen live on 9.1.9812: Edit > Copy of a glyph in the Font window, byte for byte what export returns), next to its own vic/* formats. copy_to_clipboard writes application/json plus the JSON as plain text; read_clipboard reads application/json, then the older application/x-fontlab-objects+json, then plain text.

    Limits: whether FontLab's Edit > Paste accepts our clipboard without its vic/* formats is not verified live. Components in pasted glyphs keep their base names; a base missing from the target font is not created. Unicode values are dropped from renamed glyphs; other Unicode clashes are not checked.

    How to use::

    from fontlabapp.objects import json_data
raw = json_data.export(package, [glyph])        # bytes, UTF-8 JSON
env = json_data.Envelope.parse(raw)
print("\n".join(json_data.describe(env)))
env = json_data.rename_glyphs(env, {"o": "o.alt"})
json_data.paste_glyphs(package, env, facts=scan_auto_facts(package))
